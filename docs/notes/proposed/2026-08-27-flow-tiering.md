# flow 分层与内部取数调度

Status: proposed

## Problem

flow 是一条线性管道：每个 `FlowItem` 求值自己的规则，命中就把节点追加进池，管道走完后一次性 `poolize` 做加权随机。管道没有"层"的概念，"某类客户端优先走某组节点"只能用大权重模拟，配置里因此出现成片的 `999`。这带来三个问题。

优先级是概率而不是保证。相对普通节点的个位数权重，`999` 只是把落到其它节点的概率压得很小，压不到零；而"没随到"时的行为无法预测，也无法在配置上表达"只有这层全挂了才允许往下"。同 tier 内权重回归流量配比这件事另有前提，见[加权随机选点的区间边界](../implemented/2026-08-27-weighted-selection-boundary.md)。

权重被迫承担两种语义。一部分权重是刻意的流量配比——CDN 与普通节点之间维持的比例，用来在流量成本与普通节点负载之间取平衡，普通节点跑起来比 CDN 便宜得多，比例配错任一方向都有真实代价。另一部分权重是伪优先级。两者混在同一个数字里，调一个必然动另一个，且从配置上分不出哪个是哪个。

跨层降级无法表达。`FlowItem.r#break` 是唯一的提前退出手段，但它在 `execute_flow_item` 末尾以 `Ok(item.r#break)` 返回，位置在 `if should_exec` 块之外，因此只要某层写了 `break: true` 就无条件中断整条管道，与该层规则是否命中无关。即使把返回移进条件块，`break` 表达的也只是"命中即停"，仍无法表达"本层节点全部不可用才降级"——后者要求选点逻辑知道层的边界。

另一个缺口是内部取数没有独立的调度语义。调度器自己拉取文件时（版本文件普查、KachinaInstaller 解析、缓存回填）没有客户端 IP，`client_ip: None` 让所有 IP 类条件求值为 `false`，请求被动落到兜底层，而兜底层是否适合内部取数纯属偶然。同时内部取数用 `ClientCapabilities::default()`（全 `false`），把 `h3_only`、`ssh_only`、`dfs_sftp` 节点全部排除，尽管 `FETCH_CLIENT` 自身支持这些传输。内部取数因此走在一条既非本意、也不受配置控制的路径上。

## Proposal

**显式 tier。** `FlowItem` 增加 tier 序号，缺省视为同一层。池子按 tier 分组，`poolize_from_pool` 先在最低 tier 内做加权随机，仅当该 tier 内所有节点都不可用（健康检查失败、能力门控排除、落在 `banned` 里）时才降到下一 tier。插件产出的节点继承所在层的 tier。选中后记录选自哪个 tier，使日志能区分"正常选点"与"发生了降级"。同一 tier 内的权重回归单一语义：流量配比。

**break 改命令，并补 continue。** 移除 `FlowItem.r#break` 字段，改为 `use` 列表里的命令：`break` 中断整条管道，`continue` 跳过本层剩余操作但管道继续。命令位于 `use` 内，因此只在 `should_exec` 为真时执行，当前那个无条件中断的行为随字段一起消失。`poolize` 支持 `poolize break-on-hit`，表示选中即中断，避免"先写 poolize 再单独写一行 break"的割裂写法。`FlowUse` 的反序列化对这些带参形式改用前缀匹配。

**not 语义。** 增加 `FlowCond::Not(Box<FlowCond>)`，配置写 `not geoip <地区>`。分层之后这是必需的：兜底层要表达"除某地区之外的海外客户端"，否则上层节点故障时该地区的客户端会跌进一个对他们更差的层——而那一层的存在本来就是为了服务其余地区。

**internal 条件与内部上下文。** `FlowContext` 增加 `internal: bool`，新增 `FlowCond::Internal(bool)` 据此求值。内部取数改用统一构造的上下文：能力集取调度器自身的能力（h3、ssh、sftp 为真，wt、wrtc 为假），`internal` 为真。缓存回填改走这条内部路径，不再复用客户端路径。内部取数在其允许的节点全部失败时直接返回 `NO_RES_AVAILABLE`，不降级到其它节点：内部取数的结果会写进缓存并分发给所有客户端，从一个不该用的节点取到的内容会被放大，宁可显式失败让监控报出来或让人提工单。缓存条目已经记录供出节点，见[缓存条目记录供出节点](../implemented/2026-08-27-cache-provenance.md)，因此内部取数选中的节点在事后可追溯。

**配置侧随之调整。**

- `ru_gcore` 提到 tier 1，权重降回个位数。原先为防其故障而堆的海外大带宽节点由 tier 降级机制承担，不必再靠权重表达。
- `global_cf` 加 `not geoip <该地区>` 并置于 tier 2，使 tier 1 故障时该地区客户端继续往下走而不是落到 CF。
- `cernet2_step` 与 `global_cf` 同 tier；它当前的优先级不足，分层后可以恢复原意。
- `h3_37` 加 `cnip true`，作为国内 IPv6 加 h3 客户端的层。
- `cdn_step`、`eo_1m_step`、`large_file_cnb` 的权重保持不变。这些是刻意的流量配比：改成 tier 会让流量包被快速烧完，改小则普通节点被打满。CDN 在额度耗尽时自身返回 5xx/4xx 停服，由健康检查移出池子，不需要 flow 侧表达额度。
- 测试版资源（`BetterGI.Alpha.exe`）的 flow 去掉海外两层。该资源的测试版本不做全局分发，命中的版本号在普通节点上都没有文件，其 `server cnb 100` 表达的是"唯一有文件的节点"而非优先级，不转 tier。
- 核实 flow 中引用但未在 `servers` 中定义的节点，要么补定义要么删引用。

**验证器补两条。** flow 引用未定义的节点应当报错，而不是静默进池、等健康检查阶段剔除；`break` 之后不可达的层应当报出。

## Alternatives considered

**继续用大权重模拟优先级。** 落选：概率性而非保证，且强迫权重承担两种语义。加大到 `999999` 只是把概率压得更低，压不到零，而"没随到"时选中的正是本该避开的节点。

**只修 break 的条件判断，不引入 tier。** 落选：`break` 只能表达"命中即停"。跨层降级要表达的是"本层节点全部不可用才往下"，这要求选点逻辑知道层的边界，管道级的中断做不到。

**只做 tier，不做 break 与 continue。** 落选：层内仍需要提前退出，tier 只定义顺序与降级条件，不管层内控制流。

**保留 `break` 为字段，只把返回移进 `should_exec`。** 落选：字段形式把控制流写在层的属性里而不是操作序列里，读配置时要跳出 `use` 才能知道这层会不会中断；`poolize` 与 `break` 的先后关系也无法表达。

**用 priority 数字字段代替 tier。** 与 tier 等价，差别在命名。选 tier 是因为它直呼"层"，而 priority 容易与权重被读成同一维度上的两个数值。

**内部取数沿用客户端路径，靠 `client_ip: None` 落兜底层。** 落选：这是现状。兜底层是否适合内部取数是偶然结果，且全 `false` 的能力集排除了调度器实际支持的传输。

**内部取数失败时降级到任意可用节点。** 落选：结果会写进缓存并分发，错误来源会被放大。

**给内部层配 `999999` 权重而不是独立 tier。** 落选：内部取数上"有概率没随到但不至于完全挂掉"这个取舍不成立——没随到时取到的是错误来源的内容，且它会被缓存。

## Acceptance criteria

- 同 tier 内存在可用节点时不降级；该 tier 内节点全部不可用时降到下一 tier。
- 配置中不再有仅为表达优先级而存在的 `999` 类权重；作为流量配比的权重保持原值。
- `break` 只在所属层规则命中时生效；`continue` 跳过本层剩余操作且管道继续。
- `not <cond>` 可解析、可序列化回等价文本，求值结果为对应条件的取反。
- 内部上下文下 `internal true` 命中，`h3_only` 与 `dfs_sftp` 节点可进池，`wrtc` 类节点不进池。
- 内部取数在允许的节点全部失败时返回 `NO_RES_AVAILABLE`，且不写入缓存。
- `dfs2 validate` 对引用未定义节点的 flow 报错，并报出 `break` 之后不可达的层。
- 日志能看出本次选点来自哪个 tier。

## Risks

tier 引入新的失败模式：某层条件写得过窄会导致该层无节点可用而降级，日志上表现为"降级"而非"配置错误"。区分二者依赖 validate 的静态检查与 tier 选点日志，两者都要到位。

迁移期语义会变。清掉伪优先级权重的同时若 tier 划分与原意不符，流量分布会明显偏移。建议按资源逐个迁移并观察分布，而不是一次改完。

`break` 从字段改成命令是配置的不兼容变更。由于该字段当前无条件中断，任何用到它的层的实际行为都已经与配置意图不符，迁移时必须逐层重新判断意图，不能机械替换为 `use: [break]`。

内部取数改为显式失败后，配置错误的表现从"悄悄从错误节点取数"变为"内部取数停摆"，可观测性更好但影响更直接：版本文件普查与缓存回填会在配置错误时中止。这要求 `NO_RES_AVAILABLE` 有对应指标与告警，否则只是把静默错误换成了静默不可用。

内部能力集是硬编码常量，与 `FETCH_CLIENT` 的实际能力之间没有强制关联，两者可能随中间件调整而脱节。
